DFT 실습 [1] — 맥북에서 인생 첫 계산까지, 89.5초의 기록

계획표에는 "첫 테스트 계산: 다음 주 금요일"이라고 적혀 있었습니다. 그런데 일요일 밤, 예정보다 닷새 먼저 첫 에너지를 봤습니다. −66.67098103 eV. 걸린 시간 89.5초. 그 숫자 하나를 보기까지 한 일들을 처음 하는 사람의 눈높이에서 기록해 둡니다. SSH 접속, 스케줄러 파악, POTCAR 라이브러리 정리, 입력 파일 작성, 그리고 로그 읽는 법까지. 이 글의 개념적 배경은 이론 [1]에 있습니다.

0. 무기: 터미널과 VS Code

연구실 계산 서버(클러스터)는 리눅스 기계이고, 맥에서는 별도 프로그램 없이 터미널로 바로 접속됩니다. 보안상 주소는 가리고 형태만 적으면: 

# 접속 (포트가 표준이 아니면 -p 필수)
ssh -p <포트> <계정>@<서버주소>

# 매번 치기 귀찮으니 ~/.ssh/config에 등록
Host lab
    HostName <서버주소>
    Port <포트>
    User <계정>

# 이후로는 이 두 글자면 끝
ssh lab

여기에 하나를 더 얹으면 작업 환경이 완성됩니다. VS Code의 Remote-SSH 확장. 연결하면 왼쪽엔 서버의 파일 트리, 가운데엔 편집기, 아래엔 서버 터미널이 한 화면에 뜹니다. 서버의 입력 파일을 맥 앱처럼 편집하고, 같은 창에서 잡을 던집니다. 계산 연구자의 콕핏입니다.

그리고 이 콕핏이 첫 교훈도 줬습니다. 터미널에 여러 줄짜리 명령을 통째로 붙여넣다가 연결이 잠깐 끊기면서 파일이 반토막 나는 사고가 있었습니다. 그날 배운 것: 여러 줄 파일은 터미널이 아니라 편집기로 만든다. 도구가 있는데 굳이 곡예를 할 이유가 없었습니다.

1. 지형 파악, 로그인 메시지는 읽으라고 있는 것

처음 접속하면 환영 메시지가 길게 뜹니다. 그냥 넘기기 쉬운데, 사실 그 안에 필요한 정보가 다 있었습니다. 이 클러스터는 PBS라는 스케줄러로 계산 자원을 배분하고(계산을 직접 실행하는 게 아니라 "잡"을 제출하면 스케줄러가 빈 노드에 태워 줍니다), 잡 제출은 qsub, 조회는 qstat, 취소는 qdel이라는 것까지 친절하게 적혀 있었습니다.

나머지 지형은 명령 몇 개로 파악됩니다:

module avail   # 설치된 소프트웨어 목록 → VASP 6.4.3 발견
pbsnodes -a    # 노드 사양 → 6코어/12코어 혼재, 노드당 램 32GB
df -h          # 디스크 → 홈 파티션 95% 사용(!), /data는 7.3TB 널널

마지막 줄이 중요했습니다. 홈 디렉토리가 있는 디스크는 거의 가득 차 있었고, 실제 작업은 큰 디스크에서 해야 했습니다. 비유하면 홈은 좁은 원룸(설정 파일만), 데이터 파티션이 작업실(계산 전부)입니다. 그리고 터미널에서 길을 잃을 때마다 저를 구해 준 세 명령도 적어 둡니다. pwd(나 지금 어디?), ls(여기 뭐 있어?), cd(이동). 이 셋만 있으면 안 무섭습니다.

2. POTCAR, 라이선스 자료를 쓸 수 있게 만들기

DFT 계산에는 원소마다 "유사퍼텐셜" 데이터(POTCAR)가 필요합니다. 이론편에서 말한, 심층 전자를 얼려 두고 원자가 전자만 계산하게 해 주는 부품입니다. 이건 VASP 라이선스에 묶인 유료 자료라 아무 데서나 받을 수 없고, 같은 라이선스를 쓰는 연구실 구성원에게 정식으로 받는 게 원래 경로입니다.

받아 보니 원소 170개 폴더가 들어 있는데, 상태가 뒤죽박죽이었습니다. 어떤 폴더는 파일이 풀려 있고(29개), 어떤 폴더는 폴더 안에 폴더가 중첩돼 있고(12개), 대부분은 압축된 채였습니다(123개). 이대로면 스크립트가 원소마다 다르게 동작합니다. 반복문 하나로 전부 "평문 POTCAR 파일" 형태로 통일했습니다: 

cd pp_PBE
for d in */; do
  el=${d%/}
  if   [ -f "$el/POTCAR" ];        then :                      # 이미 정상
  elif [ -f "$el/POTCAR/POTCAR" ]; then mv "$el/POTCAR" "$el/POTCAR_dir" \
       && mv "$el/POTCAR_dir/POTCAR" "$el/POTCAR" && rm -rf "$el/POTCAR_dir"
  elif [ -f "$el/POTCAR.Z" ];      then zcat "$el/POTCAR.Z" > "$el/POTCAR"
  fi
done

# 검증: 누락 폴더 수 → 0이 나와야 통과
for d in */; do [ -f "${d}POTCAR" ] || echo "누락: $d"; done | wc -l

0. 170개 전부 통과했습니다. 정리하면서 배운 부수 지식: 압축 상태의 파일에서도 ENMAX라는 값을 읽을 수 있는데, 이게 각 원소가 요구하는 평면파 해상도의 하한입니다. 제 원소들 중 최댓값이 산소의 400 eV였고, 관례(최대값 ×1.3)에 따라 뒤에 나올 ENCUT을 520 eV로 정하는 근거가 됐습니다. 설정값 하나에도 출처가 있다는 걸 처음 실감했습니다.

3. 입력 파일 4종, 계산 하나의 해부도

VASP 계산 하나는 파일 4개로 정의됩니다. 각각이 이론편 대응표의 부품 하나씩입니다.

  • POSCAR. 무엇이 어디에 있는가. 저는 층상 산화물 NaMnO₂의 이상화된 구조(12원자)를 썼습니다. 첫 계산은 "돌아가는지 확인"이 목적이라 단순한 구조면 충분합니다.
  • POTCAR. 원소 데이터. 위 라이브러리에서 Na, Mn, O 세 파일을 POSCAR의 원소 순서 그대로 이어 붙입니다(cat Na_pv/POTCAR Mn_pv/POTCAR O/POTCAR > POTCAR). 순서가 어긋나면 나트륨을 망간으로 계산하는 대참사가 조용히 일어납니다.
  • KPOINTS. 샘플링 밀도. 6×6×2로 잡았습니다.
  • INCAR. 나머지 모든 설정:
SYSTEM = NaMnO2 smoke test (static SCF)
ENCUT  = 520          # 평면파 해상도 (산소 ENMAX 400 × 1.3)
EDIFF  = 1E-5         # SCF 수렴 판정 기준
ISMEAR = 0
SIGMA  = 0.05
ISPIN  = 2            # 스핀 켜기 (자성 물질 필수)
MAGMOM = 3*0.0 3*4.0 6*0.0   # Na 0, Mn 4μB(고스핀 Mn3+ 가설), O 0
NSW    = 0            # 원자 안 움직임 — 전자 문제만 (SCF만)
IBRION = -1

두 군데에 저의 "물리적 주장"이 들어 있습니다. 하나는 MAGMOM입니다. 망간이 +3가 고스핀 상태(스핀 4μB)일 거라는 초기 가설을 계산에 심는 겁니다. 전이금속 산화물은 이 초기값에 따라 다른 답으로 수렴해 버릴 수 있어서, 아무렇게나 주면 안 된다고 배웠습니다. 결과에서 이 가설이 검증되는 장면이 뒤에 나옵니다.

다른 하나는 KPOINTS의 6×6×2. 처음엔 "너무 촘촘한 것 아닌가?" 싶었는데, 규칙을 알고 나니 반대였습니다. k점 개수는 실공간 축 길이에 반비례합니다. 이 셀은 a축이 2.95Å로 짧고(→ 6개 필요) c축이 15.8Å로 길어서(→ 2개면 충분), 축 길이 × k점 수가 두 방향 모두 관례 범위(대략 20~30Å)에 들어옵니다. 감이 아니라 곱셈으로 확인할 수 있는 문제였습니다.

4. 잡스크립트, 선배의 파일이 최고의 문서였다

제 작업 공간에는 선배가 남겨 둔 예제 폴더가 하나 있었고, 그 안의 잡스크립트가 이 클러스터의 검증된 실행 레시피였습니다. 공식 문서보다 귀한 이유: "이 기계에서 실제로 돌아간다"가 이미 증명돼 있기 때문입니다. 핵심만 남기고 정리한 버전: 

#!/bin/bash
#PBS -N NaMnO2_test
#PBS -l walltime=24:00:00
#PBS -l select=1:ncpus=6:mpiprocs=6:ompthreads=1
#PBS -j oe

module purge
module load ohpc
source /opt/.../mkl/env/vars.sh intel64   # ← 이 줄이 비법. 없으면 실행 자체가 안 됨

cd $PBS_O_WORKDIR
mpirun -np 6 -hostfile $PBS_NODEFILE .../bin/vasp_std > vasp.log 2>&1

혼자였다면 절대 몰랐을 한 줄이 저 source ... mkl ...입니다. VASP가 수학 라이브러리(MKL)를 찾으려면 환경을 먼저 불러와야 하는데, 이건 문서 어디에도 없고 그 스크립트에만 있었습니다. 선배 원본에는 여러 구조를 연달아 돌리는 반복문과 결과를 표로 뽑는 후처리도 있었는데, 첫 계산에는 불필요해서 뺐습니다. 대신 다음 단계인 수렴 테스트 자동화에서 그 패턴을 그대로 빌려 쓸 예정입니다.

5. 발사, 그리고 로그 읽는 법

qsub jobscript     # 제출 → 잡 번호가 나온다
qstat -ans         # 대기열 확인 → 내 잡이 R(running)

잡이 돌기 시작하면 vasp.log에 이런 줄들이 올라옵니다. 이론편의 SCF 루프가 실황 중계되는 겁니다. 한 줄이 반복 1회입니다: 

DAV:   1     0.136208094712E+04    0.13621E+04  ...
DAV:   2     0.107887772931E+03   -0.12542E+04  ...
DAV:   3    -0.876899047355E+02   -0.19558E+03  ...
   ...
DAV:   6    -0.126879150511E+03   -0.25987E+02  ...
DAV:   7    -0.685474927833E+02    0.58332E+02  ...   ← 요동!

둘째 열이 에너지입니다. +1362에서 출발해 몇 스텝 만에 −100 근처로 떨어지더니, 6~7번째 스텝에서 −127 → −68로 크게 출렁였습니다. 처음엔 뭔가 잘못된 줄 알았는데, 알고 보니 자성 있는 전이금속에서 흔한 스핀 상태가 자리 잡는 몸부림이었습니다. 초기 밀도 추측이 엉터리인 상태에서 시작해 점점 자기일관된 답으로 조여 가는, 닭과 달걀 문제를 반복으로 푸는 소리입니다. 그리고 23번째 줄에서: 

DAV:  23    -0.666709810253E+02    0.53622E-05   ...
   1 F= -.66670981E+02  E0= -.66666258E+02  ...  mag=    11.9991

에너지 변화가 5×10⁻⁶ eV로 제가 정한 기준(EDIFF=1E-5) 아래로 들어와 루프가 멈췄습니다. 최종 확인: 

$ grep "free  energy" OUTCAR
  free  energy   TOTEN  =       -66.67098103 eV

$ grep -A2 "General timing" OUTCAR
  Total CPU time used (sec):       89.528

6. 숫자 세 개의 의미

결과에서 챙길 숫자는 셋입니다.

  • E = −66.671 eV. 12원자 셀의 총 에너지. 이 절대값 자체는 아무 의미가 없습니다(기준점이 임의라서). 앞으로 모든 연구는 이 숫자의 차이(구조 A vs B, 이온이 있을 때 vs 없을 때)로 이루어집니다.
  • mag = 11.9991 ≈ 12.0 μB. 오늘의 하이라이트입니다. 셀에 망간이 3개 있고, 제가 INCAR에 심은 가설은 "Mn³⁺ 고스핀 = 개당 4μB"였습니다. 3 × 4 = 12. 계산이 그 상태로 정확히 수렴했다는 뜻이고, 자기모멘트로 산화수를 읽는다는 교과서 문장이 처음으로 제 데이터에서 작동한 순간입니다. 만약 망간이 3가가 아니었다면 이 숫자는 다르게 나왔을 겁니다.
  • 89.5초. 계산 비용의 감각. 12원자 SCF가 6코어에서 1분 반. 다만 DFT 비용은 대략 원자 수의 세제곱으로 뛰기 때문에, 본 연구에서 다룰 100원자급 셀은 같은 계산이 반나절~하루가 됩니다. "작은 셀에서 세팅을 완성하고, 큰 셀은 한 방에"가 철칙인 이유를 몸으로 이해했습니다.

이날 배운 것들

  • 숫자가 나왔다 ≠ 믿을 수 있다. 수렴 판정(EDIFF)을 통과했는지가 먼저다. 수렴 안 된 계산도 숫자는 뱉는다.
  • 설정값에는 출처가 있다. ENCUT 520은 POTCAR의 ENMAX에서, k점 6×6×2는 축 길이 반비례 규칙에서 나왔다. "남들이 쓰길래"는 출처가 아니다.
  • 선배의 작업 흔적이 최고의 문서다. 검증된 잡스크립트 하나가 공식 매뉴얼 열 페이지보다 빨랐다.
  • 환경의 지형부터 그린다. 홈과 데이터 파티션의 구분, 스케줄러 종류, 노드 사양. 계산보다 이걸 먼저 알아야 했다.
  • 랩노트는 그날 쓴다. 마지막으로 한 일은 노트에 한 줄 남기기였습니다: "첫 자력 DFT 성공. NaMnO₂ 12원자, SCF 23스텝 수렴, E=−66.671 eV, mag=12.0 (Mn³⁺ 고스핀 확인)." "그때 왜 그랬지"의 90%는 이 한 줄이 예방한다고 합니다.

다음 단계. 오늘 계산은 "돌아가는가"의 확인이었습니다. 다음은 "믿을 수 있는가"입니다. ENCUT을 400에서 700까지 올려 가며 에너지가 어디서부터 변하지 않는지(수렴하는지) 확인하는 테스트입니다. 이론편에서 "해상도"라고 비유했던 그 개념이 그래프 한 장의 데이터가 되는 순간을, 다음 글로 가져오겠습니다.
