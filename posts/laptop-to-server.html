노트북을 24시간 서버로 만들어 본 기록

팀에 화면을 보여줘야 하는데 아직 배포할 단계는 아니었습니다. 내 노트북에서 도는 걸 그대로 보여주는 방법을 찾다가, 터널이 무엇인지 제대로 알게 됐습니다.

1단계 — 임시 터널, 그리고 매번 바뀌는 주소

처음엔 임시 터널을 썼습니다. 명령 한 줄이면 무작위 주소가 나오고, 그 주소로 들어오면 내 컴퓨터의 로컬 서버로 연결됩니다. 설치도 계정도 필요 없어서 좋았습니다.

문제는 터널을 다시 켤 때마다 주소가 바뀐다는 것이었습니다. 공유한 링크가 계속 죽고, 링크를 다시 보내야 하고, 그 주소를 설정 파일에 넣어 둔 곳도 매번 고쳐야 했습니다. 게다가 무작위 단어를 이어 붙인 주소는 남에게 보내기에 미덥지 않게 생겼습니다.

관측

편의를 위해 도입한 것이 매번 손이 가는 일을 만들고 있었습니다. 링크를 다시 만드는 작업 자체는 1분이지만, 그게 반복되면 "지금은 그냥 보여주지 말자"가 됩니다.

2단계 — 고정 주소를 찾아서

회사 도메인에 고정 서브도메인을 붙이려 했지만, 그 도메인의 DNS가 우리가 쓰려던 서비스 바깥에 있어 바로는 안 됐습니다. 도메인을 옮기는 건 저 혼자 결정할 일이 아니었습니다.

그래서 도메인이 필요 없는 방식으로 방향을 틀었습니다. 기기마다 고정 이름을 주는 사설 네트워크 도구를 쓰고, 그중 외부 공개 기능을 켜는 방식입니다. 도메인 없이도 기기이름.네트워크이름.ts.net 형태의 고정 HTTPS 주소가 나옵니다.

여기서 막힌 것들

  • 회사 계정으로 로그인했더니 관리자 승인 대기에 걸렸습니다. 이미 회사가 쓰고 있는 네트워크였고, 저는 그 관리자가 아니었습니다. 외부 공개 기능도 조직 정책에서 잠겨 있었습니다.
  • 개인 계정으로 새 네트워크를 만들어 우회했습니다. 첫 시도는 "그런 네트워크가 없다"는 오류가 났는데, 안내대로 한 번 더 시도하니 새로 만들 것인지 묻는 화면이 나왔습니다.
  • HTTPS 인증서가 꺼져 있어 실패했습니다. 관리 화면에서 켜자, 도구가 자동으로 인증서를 발급받았습니다. 로그를 보니 DNS 방식으로 소유권을 증명하고 있었습니다.

인증서를 받은 직후 접속하니 연결이 끊겼는데, 잠시 뒤 다시 하니 정상이었습니다. 발급과 반영 사이의 몇 초짜리 시차였습니다. 이런 건 로그를 보지 않으면 원인을 영원히 모릅니다.

배운 것 — 터널은 사본이 아니라 길이다

여기서 개념 하나가 분명해졌습니다. 고정 주소를 얻고 나니 마치 어딘가에 배포한 것 같은 착각이 들었는데, 실제로 일어나는 일은 전혀 달랐습니다.

그래서 노트북 뚜껑을 닫으면 링크가 죽습니다. 전원을 꺼도 마찬가지입니다. 반대로 진짜 호스팅은 앱과 데이터의 사본이 남의 서버에 올라가므로 내 기기와 무관하게 살아 있지만, 데이터가 내 손을 떠난다는 결정이 따라옵니다. 공짜 점심은 없고, 무엇을 내줄지 고르는 문제였습니다.

재부팅에도 살아남게 만들기

터미널에서 띄운 프로세스는 창을 닫으면 사라집니다. macOS의 사용자 단위 서비스 관리자에 두 개를 등록했습니다 — 네트워크 데몬 하나, 앱 서버 하나. 재부팅해도 로그인만 하면 알아서 올라옵니다.

여기서 알게 된 요령 하나. 네트워크 도구를 사용자 공간 모드로 돌리면 가상 네트워크 장치를 만들지 않아 관리자 권한이 필요 없습니다. 원래는 시스템 서비스로 등록해야 했을 것을, 사용자 서비스로 끝낼 수 있었습니다. 권한을 덜 쓰는 쪽이 대개 나중이 편합니다.

가장 오래 헤맨 건 권한 한 줄이었다

마지막에 코드를 저장소에 올리려고 CLI 인증을 했습니다. 브라우저 인증까지 통과하고 "인증 완료"가 떴는데, 정작 다음 명령은 "로그인되어 있지 않다"고 했습니다.

원인은 로그 맨 끝 한 줄이었습니다. 

✓ Authentication complete.
mkdir /Users/me/.config: permission denied

홈 디렉터리 안의 설정 폴더가 root 소유로 만들어져 있었습니다. 언젠가 어떤 설치 프로그램이 관리자 권한으로 만들어 놓고 소유권을 되돌리지 않은 것입니다. 인증은 성공했지만 토큰을 저장할 폴더를 만들 수 없어 그대로 사라지고 있었습니다.

소유권을 되돌리자 한 번에 해결됐습니다. 교훈은 "성공했다"는 메시지 뒤의 줄을 읽자였습니다. 앞에서 성공을 보고 나면 뒤의 실패를 건너뛰게 됩니다. 그리고 이 폴더는 다른 도구들도 함께 쓰는 곳이라, 아마 조용히 여러 개가 막혀 있었을 겁니다.

남긴 규칙

링크의 수명은 그 링크가 가리키는 기계의 수명이다. 그리고 성공 메시지 다음 줄을 읽는다.

지금 쓰는 방식

터널(지금) 클라우드 호스팅
기기를 꺼도 링크 죽음 살아 있음
데이터 위치 내 기기에서 안 나감 외부 서버로 나감
비용 없음 월 사용료
접근 제어 링크를 아는 사람 설정하기 나름

지금은 터널 쪽에 있습니다. 데이터가 기기를 떠나지 않는다는 점이 현 단계에서 가장 큰 장점이고, 대신 "보여줄 때 기기가 깨어 있어야 한다"는 제약을 안고 갑니다. 이 제약이 불편해지는 순간이 배포를 결정할 시점일 것입니다.
